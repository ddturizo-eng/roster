## What Roster is now

`roster` drives features of registered projects from idea to reviewable PRs, running each task in a
hardened Docker container through Claude Code headless on the human's Claude Pro subscription. Git
holds intent (specs, plans, `tasks.md`, ADRs, agents); a local SQLite store will hold progress.
Linear is frozen (ADR 0014). Roster builds itself first, then the human's 1-2 apps.

## How each task runs (bootstrap, until T24)

1. `git checkout main && git pull`, then `git checkout -b agent/002-<Tnn>`.
2. Launch the task's `Agent:` from `tasks.md` as a subagent in **Mode A** (supervised): it writes code
   and tests, runs `npm run typecheck` / `npm test`, never runs `git commit`/`push`/`gh`, never edits
   `tasks.md`, stays inside the task's Areas, stops and asks when ambiguous.
3. The supervising session verifies (`npm ci`, typecheck, tests), checks the `Done` box, commits only
   the task's paths, pushes, opens a PR with what/choices/follow-ups/verification.
4. The human merges. CI (`.github/workflows/ci.yml`) runs on PRs.
5. Protected paths (ADR 0025: `.github/workflows/**`, `agents/**`, policies, guards, constitution...):
   the human pushes or approves by merging.
6. One executing agent at a time (quota). Parallel doc work goes in an isolated git worktree so it never
   touches the task branch; remove the worktree after merge.

Agent models (PR #13): Sonnet for `roster-core-ts-engineer`, `roster-sqlite-store-engineer`,
`roster-windows-powershell-engineer`, `roster-agent-definitions-engineer`, `technical-writer`; Opus for
`architect`, `hr-director`, `roster-boundary-adapters-engineer`, `roster-container-devops-engineer`.
After merging, start a new session so Claude Code reloads `.claude/agents/`.

## Decisions and conventions already settled

- Layering (T01): `core` imports no Node built-ins; `ports` import only `core/domain`; adapters import
  `core` and `ports`, never other adapters or `cli`.
- T02 choices: execution statuses include `blocked`; text limits 4000/2000 chars, result file 256 KiB;
  `RuntimeJob.limits` arrive already capped by policy.
- T03 choices: `nightWindow` is `"HH:MM-HH:MM"`; `rosterRepo`, `workspaceRoot`, `commitAuthor` required;
  unknown config keys are errors.
- Plan 002 section 17 answers: `roster retry <task> --note`; `--approve-dependencies`; review never
  blocks; verification failure pushes the branch without PR; closed PR → `rejected`; night window
  22:00-06:00, 5 runs; max 3 grilling rounds.
